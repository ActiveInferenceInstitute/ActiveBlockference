# Reproducibility and release procedure {#sec:reproducibility}

The repository records the exact runtime dependency graph in `uv.lock` and
uses `uv sync --locked --extra dev` for development. The release procedure is:

```bash
uv sync --locked --extra dev
GNN_RUNTIME_PYTHON="${GNN_RUNTIME_PYTHON:?Set the external pinned GNN runtime Python}" \
uv run python {{gate_entry_point}} --arm all
```

The release selection requires a separately configured external GNN runtime at
the pinned revision, named by `GNN_RUNTIME_PYTHON` (or a pinned checkout named by
`GNN_ROOT`); see [`../gnn.md`](../gnn.md) for setup. The `gnn` arm always performs
real pinned validation and fails when that runtime is unavailable. The gate has
separately runnable arms (`--list` shows them); `--arm all` is the release
selection and the fast default is used while editing.

The generative-model declaration is checked against the pinned upstream parser:
`{{gnn_pin_path}}` records schema `{{gnn_pin_schema}}`, tag `{{gnn_tag}}`, and
commit `{{gnn_commit}}`. The conformance job key is `{{gnn_job_key}}` with
display name `{{gnn_job_name}}`; the pointer
[`../../.github/GNN.md`](../../.github/GNN.md) records exactly what that job
parses.

The canonical command emits a run tree whose completed `manifest.json` and
independently written `validation_report.json` agree. `PipelineResult.ok` and
`ValidationReport.ok` remain the only release verdicts. The smoke output root
is temporary, so generated runs do not become source files.

The seed is consumed by an experiment-local NumPy generator. Repeating a
configuration therefore repeats targets and sampled actions without changing
the caller's process-global Python or NumPy random streams. For multi-agent
experiments, use `simulation.initial_states` when the starting coordinates must
be distinct or otherwise explicit.

## Provenance of the figures

The loop in [@fig:loop], collision diagram in [@fig:collision], and pipeline
diagram in [@fig:release-contract] are structural diagrams generated by the
manuscript builder. The seeded-run figure [@fig:seeded-run] is computed from a
seeded `run_experiment` call with the configuration recorded in
[@tbl:reference-run]. The figure generator imports the public package API and
uses the same action vocabulary and simulation semantics as the release
pipeline. `figure-registry.json` declares each source label and its SVG/PNG
companions; source validation and both build/check paths reject registry,
reference, or generated-filename drift.
